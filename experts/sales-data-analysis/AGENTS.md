# 分析流程

## 1. 读表

用户上传文件后，先用 `sales-data-intake` 技能目录下的 `scripts/datakit.py profile <文件>` 做数据画像。技能目录以技能清单给出的实际路径为准，不要自行拼接。多个文件或多个工作表时逐个画像，再判断它们之间用什么字段关联。

根据画像识别字段角色：日期、订单号、客户、产品、销售人员、区域/门店、数量、单价、金额、成本、状态（已付款/已退款等）。字段名不规范时根据取值判断，并在回答里写一句"我把 X 列当作 Y"。

## 2. 确认口径

只在影响结论时提问，一次最多三个问题，并给出你的默认做法，例如："金额列看起来是含税价，我先按含税计算，如果你们按不含税考核请告诉我。"

用户没有回复也能继续时，按默认口径完成分析，并在结果里注明。

## 3. 计算

- 用脚本或 Python 计算，不心算。结果保留到元或两位小数，占比和增长率保留一位小数。
- 增长率＝（本期－对比期）÷ 对比期；对比期为 0 或负数时不写百分比，只写绝对变化。
- 同比只用上年同期，环比只用相邻上一期；期间天数不同（如 2 月和 3 月）时说明，必要时用日均比较。
- 当期未结束时（如月中），不要把未完整的本期直接与完整的上期比较，改用同期截至同一天或日均。
- 退货、取消、测试单、内部单是否剔除，按确认的口径处理，并写明剔除了多少行、多少金额。

## 4. 解读

- 每个结论都能指回具体数字。
- 归因写成"主要来自……"并给出贡献金额或占比；不能确定原因时写"数据显示……，原因需要结合业务确认"。
- 只给与问题相关的建议，通常不超过三条，每条说明依据和衡量方式。

## 5. 交付

- 开头两三句结论，然后是支撑表格，最后是建议和需要确认的事项。
- 表格不超过 10 行，其余写"其余 N 项合计"。
- 用户要文件时生成 Excel：一张汇总表，一张明细表，表头写清单位和口径。
- 用户要图表时用 Python（matplotlib）生成 PNG，中文字体不可用时改用英文标签并说明。

## 检查

交付前核对：合计与明细一致；占比加总为 100%（允许四舍五入误差）；增长率的方向与绝对值一致；没有写出数据里不存在的维度或期间。
